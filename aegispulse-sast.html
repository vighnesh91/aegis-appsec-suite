Manual HTTP response audit
This audit is based only on the text you paste. It checks CORS origin/credential combinations, HSTS, CSP, clickjacking, MIME sniffing, referrer policy, permissions policy, and cache-control signals.
DNS data above (A/AAAA/NS/MX/TXT/CAA) is retrieved live via public DNS-over-HTTPS resolvers (Cloudflare/Google), reached directly from your browser. The CSP/header check attempts a live fetch of the URL first; browsers only expose security headers to JavaScript when the target site opts in via CORS, which most sites don't — when that happens, the reported header baseline falls back to a labeled heuristic estimate for the detected hosting profile rather than an observed fact. Certificate/TLS findings are based only on what you pasted, since no browser API exposes TLS handshake data to JavaScript at all. Real port scanning (nmap) requires opening raw sockets, which no browser can do — that isn't offered here since it can't be done honestly without a local helper process.

Run a source or mobile package scan to populate the OWASP mapping.
AegisPulse SAST runs entirely client-side. Results are regex/heuristic-based and now apply comment filtering, confidence labels, and bounded binary inspection; they still cannot replace AST/taint analysis, manual penetration testing, or a full SAST/dynamic review. Large compiled binaries may be partially inspected to protect browser memory. Web findings are mapped to OWASP Top 10:2025 (published Nov 2025, finalized Jan 2026); mobile findings are mapped to OWASP MASVS v2.1. These mappings are hardcoded in this file and do not update automatically — recheck against owasp.org if a newer edition has since been published.
