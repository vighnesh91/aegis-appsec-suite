📚 Content Security Policy (CSP) Directives Reference Guide Expand Guide & Source Values ▾

Content Security Policy (CSP) directives control what resources (scripts, styles, images) a browser can load and execute on a webpage. They are sent via the Content-Security-Policy HTTP header to mitigate XSS attacks and unauthorized data exfiltration.

1. Fetch Directives (Resource Loading)
  • default-src: Serves as the fallback for all other fetch directives when unspecified.
  • script-src: Restricts allowed sources for JavaScript. (Variants: script-src-elem for <script> tags, script-src-attr for inline event handlers)
  • style-src: Restricts allowed sources for CSS stylesheets. (Variants: style-src-elem, style-src-attr)
  • img-src: Restricts sources for images and favicons.
  • connect-src: Restricts endpoints for fetch(), XMLHttpRequest, WebSockets, and EventSource.
  • font-src: Restricts allowed web fonts loaded via @font-face.
  • frame-src: Controls valid URLs for nested frames (<iframe>, <frame>).
  • media-src: Restricts sources for audio and video (<audio>, <video>).
  • object-src: Restricts sources for plugins (<object>, <embed>).
  • worker-src: Controls sources for Web Workers, Shared Workers, and Service Workers.
  • manifest-src: Controls application manifest files.
2. Document & Navigation Directives
  • base-uri: Restricts URLs allowed in a document's <base> element.
  • form-action: Controls valid target URLs for HTML form submissions.
  • frame-ancestors: Specifies which domains can embed current page inside <iframe> / <frame> (prevents Clickjacking).
  • sandbox: Enables standard iframe-style restrictions (e.g. blocking popups or scripts unless allowed).
3. Reporting & Enforcement Directives
  • report-uri / report-to: Specifies endpoints where browser sends JSON report payloads when violations occur.
  • upgrade-insecure-requests: Instructs browsers to automatically rewrite HTTP requests to HTTPS before loading.
  • require-trusted-types-for: Forces DOM-based XSS protections requiring Trusted Types for dangerous sinks like innerHTML.
4. Common Source Values
  • 'self': Allows resources from exact same origin (same scheme, host, and port).
  • 'none': Completely blocks loading that resource type.
  • 'unsafe-inline': Permits inline scripts/styles (increases XSS risk).
  • 'unsafe-eval': Allows string-to-code execution APIs like eval().
  • 'nonce-<base64>': Permits inline scripts/styles matching a cryptographically generated token.
