3. Decompile (apktool-style / ios-dump-style)

Android output is an apktool-like decoded tree: AndroidManifest.xml and every binary res/**/*.xml re-rendered as indented readable XML, the resources.arsc string table dumped to res/values/resources-dump.txt, and each classes*.dex parsed into smali-summary/*.txt. With full smali disassembly checked, every method body of every class is disassembled to real Smali bytecode under smali/ & smali_classesN/. iOS output mirrors it: every binary plist converted to XML, the embedded.mobileprovision payload extracted, and each Mach-O binary (the app executable and every .dylib/framework) parsed into macho/<bin>.txt, class-dump.txt, plus a readable.txt that names the binary type (executable / dylib / bundle), recovers Objective-C interfaces with their methods, disassembles each method body to ARM64 assembly (for decrypted binaries), and lists Swift/C++ symbols. Android native libraries (lib/*.so) are parsed to libelf/*.txt with their exported/imported symbols. Equivalent shell commands are echoed in the log so you can reproduce the run with apktool / class-dump / otool / swift-demangle.

Android: pure-JS Dalvik disassembler — parses the DEX string/type/proto/field/method pools and each method's code_item directly, then decodes bytecode into Smali-style instructions (covers the common instruction formats — 10x/11x/12x/21c/22c/23x/35c/3rc/51l, etc). This is a real disassembly of the bytecode, not a decompiled-to-Java reconstruction — control flow (if/for/while, exception ranges) is left as raw branches/labels, same as reading Smali from apktool.
iOS: parses each Mach-O binary's header/load commands (architectures, segments/sections, linked dylibs) and recovers Objective-C class names + selectors from the __objc_classname/__objc_methname string sections — the same signal otool -l / class-dump surface. This is a class/selector-level dump, not decompiled method bodies (Swift/ObjC implementations aren't reconstructed — that needs Hopper/IDA on the actual binary).

6. Recompile & repackage

⚠️ Jailbroken-only
Re-encodes edited manifest/plist into real binary AXML / bplist00. Android .p12 signing parses your PKCS#12 in-browser (never uploaded) and writes a real v1 JAR signature — this is enough for adb install / most third-party stores, but Play Store requires v2/v3 which needs apksigner locally. iOS fake-sign strips the existing _CodeSignature/ and embedded.mobileprovision so a jailbroken device can re-sign with ldid; installable IPAs for stock iOS still require macOS + codesign with your Apple Developer cert (no browser can produce those).

Every command from section 3's decode step is echoed again here as part of the round trip, plus the build/sign step — Android: apktool d → edit → apktool b → keytool/jarsigner. iOS: unzip → plutil → security cms (mobileprovision, read-only — not re-signed here) → edit → plutil -convert binary1 → zip → ldid. otool / class-dump are decode-only (inspecting the Mach-O binary) so they don't re-run on build, but are listed again below for reference.

12. Entropy & validated secret scanner — Shannon entropy + AWS/Stripe/GitHub/JWT checksum validation

Sweeps every text-decodable entry of the currently loaded package (section 1 or the section 7 grep source). Flags high-entropy tokens (Shannon ≥ 4.5 bits/char over 20+ chars) and validates known secret formats: AWS access keys (AKIA/ASIA 20-char), AWS secret keys (40-char base64 with entropy gate), Stripe live/test keys (sk_live_/pk_live_/rk_live_), GitHub PATs (ghp_/gho_/ghu_/ghs_/ghr_ with base62 CRC32), Google API keys (AIza + 35 chars), Slack tokens (xox[bpoare]-), Twilio (SK+32 hex), JWTs, PEM private-key blocks, Firebase URLs, Azure connection strings. Contextual dedup and false-positive suppression are on by default.

13. Network Security Config & sink XREF — NSC parser + WebView/Cipher/Runtime.exec back-trace

Locates every res/xml/*network*security*.xml in the loaded APK, parses <base-config>, <domain-config>, <trust-anchors>, <pin-set>, and <debug-overrides>, cross-references the android:networkSecurityConfig attribute in the manifest, and highlights user-trust anchors, missing pins, and cleartext-permitted domains. The sink XREF pass scans the DEX summaries and any embedded smali for dangerous sinks — WebView.addJavascriptInterface, weak Cipher.getInstance modes (DES/RC4/ECB/NoPadding), weak digests (MD5/SHA-1), Runtime.exec, SSLSocketFactory with ALLOW_ALL_HOSTNAME_VERIFIER, and reflection-based class loading — printing the caller class:method and a 3-line context window per hit.

14. APK Signature Scheme v2/v3 + zipalign — pure-JS/WebCrypto signing engine

Reads a repackaged .apk (either the last recompiled artifact from section 5, or a file you upload), performs zipalign (4-byte alignment for stored entries, 4096-byte for lib/*/*.so), computes the v2/v3 signing digests over the aligned ZIP (SHA-256 Merkle-style 1 MiB chunking with the standard 0xA5 chunk / 0x5A top prefixes), builds the SignedData / Signer blocks, RSA-signs them with your .p12, and inserts a proper APK Signing Block right before the Central Directory (with the trailing APK Sig Block 42 magic and updated EOCD offset). Output verifies with apksigner verify -v --print-certs on modern Android; a corresponding v1 JAR signature is also written when v1+v2+v3 is selected.
💡 Streaming sign computes the v2/v3 Merkle digest in 1 MiB chunks and writes the signed APK directly to a file you choose (File System Access API, Chrome/Edge/Opera) — memory-bounded, works for apps >4 GB. Generate apksigner command prints the exact apksigner/keytool CLI commands to run locally on a machine with Android SDK build-tools (needed if the target requires a real apksigner-verified signature you run outside the browser).

15. iOS CodeResources + CMS provisioning — _CodeSignature generator with .mobileprovision + .p12

Reads an .ipa, walks the Payload/*.app bundle, computes SHA-1 and SHA-256 hashes of every non-signature file, and writes a plausible _CodeSignature/CodeResources plist (v2 files + files2 layout). Embeds a user-supplied embedded.mobileprovision verbatim and, given a .p12, produces a detached PKCS#7/CMS signature over the CodeResources plist (stored at _CodeSignature/CodeResources.sig) using your certificate chain via node-forge. Limitation: this rewrites bundle-integrity metadata and the entitlements chain-of-trust, but does not re-embed a full LC_CODE_SIGNATURE superblob inside the Mach-O binary — for stock (non-jailbroken) iOS you still need codesign/iresign with a real Apple-issued identity; on jailbroken devices ldid -S is enough.
⚠️ Jailbroken-only
ATS (App Transport Security) helper: if your app needs to allow specific insecure (HTTP) endpoints, add an NSAppTransportSecurity dict. If none is present, iOS enforces the default secure policy (HTTPS-only).

16. Mach-O binary triage — read-only structural & security-posture audit

Drop an .ipa, unzips it in memory (JSZip), isolates Payload/<App>.app/<Executable>, and runs a read-only parse of the 64-bit Mach-O header + load command table — no bytes in the binary are ever modified. Reports DRM/encryption state (LC_ENCRYPTION_INFO_64), PIE hardening (MH_PIE flag), code-signature presence (LC_CODE_SIGNATURE, structural only — not cryptographically verified), and linked libraries (LC_LOAD_DYLIB).
Prerequisite: Decrypted Build Verification
  • App Store packages are natively encrypted by Apple's FairPlay DRM.
  • Sandboxed web environments cannot process encrypted Mach-O pages.
  • Deep code inspection requires a pre-decrypted payload (e.g., dumped via frida-ios-dump).
This inspector still runs its own structural check for you: the DRM / Encryption card below reads the LC_ENCRYPTION_INFO_64 cryptid flag directly from whatever binary you drop, so an encrypted build will be flagged rather than silently mis-parsed.

    17. Deep Reverse-Engineering Workflow — Ghidra / jadx / Capstone / frida-ios-dump command generator

    This tool runs 100% in-browser, so it cannot host Ghidra's decompiler or Capstone's full engine. Instead it generates the exact commands to hand your currently-loaded package to the right professional tooling: jadx (Android DEX → Java), Ghidra / IDA / Hopper (native pseudo-C), Capstone (100%-coverage disassembly), and frida-ios-dump (decrypt FairPlay binaries so the tool's own ARM64 disassembler can then read the method bodies).
